CYBERSECURITY & BACKEND ARCHITECTURE

SECURITY LAYER 1

HARDWARE-LEVEL
BIOMETRICS

Fingerprint data is never sent to the server. Authentication is handled locally via the device's secure enclave (e.g., TrustZone), transmitting only an encrypted cryptographic token for access.

SECURITY LAYER 2

SECURE FALLBACK
(MFA)

The "Using PIN" option acts as a critical secondary access method, preventing user lockouts while maintaining Multi-Factor Authentication principles.

SECURITY LAYER 3

TOKEN-BASED
SESSIONS

The "Auto-login" feature does not save passwords. Instead, it securely stores an encrypted 'Auth Token' issued by the server to maintain safe, persistent access.

SECURITY LAYER 4

ROBUST ACCOUNT
RECOVERY

Prevents account takeovers using Knowledge-Based Authentication (requiring CNIC & Phone) alongside strict Data Masking (***) to thwart shoulder surfing.

SECURITY LAYER 5

OUT-OF-BAND
AUTHENTICATION

The "Send OTP" function acts as a physical security barrier, verifying that the user is in actual possession of the registered mobile device.

SECURITY LAYER 1

MULTI-FACTOR
AUTHENTICATION

Enforces physical device verification to block remote, unauthorized password reset attempts.

SECURITY LAYER 2

RATE LIMITING &
TOKEN EXPIRY

The "Resend Code" function uses backend rate limiting to prevent SMS bombing, while OTPs act as time-bound tokens to thwart brute-force attacks.

SECURITY LAYER 3

CRYPTOGRAPHIC
HASHING

Passwords are never stored in plaintext. The backend utilizes industry-standard hashing algorithms (e.g., bcrypt/SHA-256) to secure credentials against database breaches.

SECURITY LAYER 4

GLOBAL SESSION
REVOCATION

Upon a successful password reset, the backend immediately invalidates the old password and terminates all prior active sessions across all devices to prevent compromised access.
